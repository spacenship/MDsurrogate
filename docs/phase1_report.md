# Phase 1 — 힘 조건부 단백질 MD 앙상블 모델

**상태:** 완료 (2026-08-19). 120,000 step 학습 완주, 체크포인트 `runs/phase1_full/last.pt`.

이 문서는 Phase 1의 구조, 데이터, 학습 설정, 결과를 한 곳에 정리한 것이다. 설계 근거와
미해결 사항은 `docs/open_questions.md`, 계층 구조와 상태 계약의 상세는
`docs/phase1_hierarchy_and_contracts.md`, Phase 2 인계 규약은 `docs/phase2_interface.md`에 있다.

## 1. 개요

Phase 1은 단백질의 한 프레임(원자 좌표 + 화학 정보 + 서열 + 온도)을 입력받아
**그 프레임에서 각 원자와 각 잔기에 걸리는 힘**을 예측한다. 시간 전개는 하지 않는다.
Phase 2가 그 위에 전이(transition) 모듈을 올린다.

핵심 설계 전제 — 이후 모든 해석이 여기에 걸린다:

- **순간적인 힘은 1–16 ns 뒤의 좌표를 결정하지 않는다.** 측정된 프레임 간 힘 상관은 **−0.024**다.
  Phase 1이 만드는 것은 다음 좌표가 아니라 국소 물리의 잠재 표현이다.
- **거친 잔기 계는 열린 계이고 일반적으로 비마르코프적이다.** 해밀토니안 동역학이 아니다.
- **단백질에 걸리는 알짜힘은 0이 아니다** (측정값 42.7). 용매가 단백질에 힘을 가하기 때문이다.
- **mdCATH의 힘은 하나의 force field와 프로토콜이 만든 라벨**이지 자연에 대한 참값이 아니다.
- 대칭은 **SE(3)**이지 E(3)가 아니다. 반사는 대칭이 아니며 카이랄성은 모델링 대상이다.

## 2. 구조

### 2.1 3계층 그래프

| 계층 | 노드 | 의미 |
|---|---|---|
| `B_i` | backbone frame | 잔기 i의 N/CA/C가 정의하는 국소 좌표계 |
| `R_i` | residue semantic | 잔기 i의 화학적·서열적 정체 (ESM-2 임베딩 포함) |
| `A_ia` | atom child | 잔기 i에 속한 원자 a |

메시지 전달은 `A → R → B → R → A` 순환을 **2회** 수행한다 (`encoder.num_cycles: 2`).
6개 관계(relation)를 명시적으로 구분해 유지한다 — 합치면 인코더가 조건화하는 구분이 사라진다:

```
backbone__sequence__backbone     서열 인접 (±1, ±2), chain-break 인지
backbone__spatial__backbone      CA kNN(16), 13 Å 컷오프
backbone__owns__residue          1:1
residue__contains__atom          1:N
atom__bonded__atom               PSF 결합 그래프 (거리 fallback tol 1.3)
atom__spatial__atom              5 Å 컷오프, 잔기 간 포함
```

### 2.2 등변 표현

e3nn 기반. irreps `64x0e + 16x1o + 8x2e` (lmax=2, latent dim **152**).

**텐서곱은 `uvu`(depthwise)를 쓴다.** `uvw`(fully-connected)는 edge당 8,064개 가중치가 필요해
80 GB H100에서 38 GB를 소모하다 OOM으로 죽었다. `uvu`는 입력 multiplicity를 유지하고 경로마다
가중치를 한 번씩만 두어 **edge당 288개**(28배 감소)이고, 최대 메모리 9.41 GB, 파라미터
3.17M → 1.02M로 줄었다.

> **함정:** instruction 인덱스를 만든 뒤 `.simplify()`를 호출하면 irreps 항목이 병합되어
> 인덱스가 조용히 무효화된다. `sort()`만 해야 한다.

### 2.3 데이터 표현

**flattened ragged**만 쓴다. padded dense는 어디에도 없다. 배치는 노드를 이어붙이고
`batch_index`로 소속을 표시한다. 상태 계약은 `data/contracts.py`가 강제하며,
검증은 `validate()`로 분리해 학습 경로에서 호출하지 않는다.

교차 계층 검증에 포함된 것: 배치 누출 탐지, "모든 잔기는 최소 1개 원자를 소유한다".

### 2.4 조건화

- **ESM-2** `facebook/esm2_t33_650M_UR50D` (1280차원). **동결, 사전 계산, 캐시.**
  학습 루프에서 절대 실행하지 않는다. 1000개 도메인 전부 `esm2_cache/`에 있다 (673 MB).
- **온도** 5종 (320/348/379/413/450 K) 스칼라 조건화.

### 2.5 출력 헤드

| 헤드 | 출력 | 비고 |
|---|---|---|
| `AtomicEffectiveForceHead` | 원자 힘 평균 + 대각 log-variance | 이분산 |
| `ResiduePhysicsHead` | 잔기 힘·토크 평균 + log-variance, 은닉 잔차 | 토크는 원점(CA)과 함께 저장 |
| `InvariantEnergyHead` | 스칼라 U, `-∇U` | **이번 학습에서는 비활성** (§5.3) |

log-variance는 `[-8, 8]`로 clamp된다.

### 2.6 힘의 투영

```
F_i = Σ_a f_a                       (잔기 알짜힘)
τ_i = Σ_a (x_a - r_i) × f_a         (CA 기준 토크)
τ(o') = τ(o) + (o - o') × F         (원점 이동 법칙)
```

클래스 이름은 `ResidueSumProjector` — **하는 일 그대로 붙인 이름이다.** 이것은
"constraint-aware projection"이 **아니며** 그렇게 서술해서도 안 된다. mdCATH의 힘은 구속
조건(수소 결합 강체화)이 걸린 시뮬레이션에서 나왔고, 단순히 더하는 것으로 그 구속이 풀리지 않는다.

### 2.7 손실

```
L = 1.0 · NLL(원자 힘)
  + 1.0 · NLL(잔기 힘)
  + 1.0 · NLL(잔기 토크)
  + 1.0 · MSE(은닉 잔차)
  + 0.1 · ||explained - aggregated||²      (집계 일관성)
  + 0.1 · ||-∇U - f||²                     (보존력, 이번엔 비활성)
  + 1e-4 · mean(U²)                        (에너지 게이지, 이번엔 비활성)
```

**오차는 잔기 국소 프레임에서 평가한다.** 대각 공분산은 축이 고정되어야만 의미가 있다.

**은닉 잔차는 집계 일관성 항에서 제외한다.** 그 항은 잔기의 *설명된* 힘을 예측 원자 힘의 합에
묶는데, 은닉 잔차는 정의상 표현되지 않은 원자가 담당하는 부분이다. 포함하면 두 항이 서로를
상쇄하도록 요구하게 되고, 모델이 잔차에 임의의 질량을 숨길 수 있게 된다.

## 3. 데이터

### 3.1 mdCATH

`compsciencelab/mdCATH`, 스키마 `mdcath-only-protein-v1.0`.

| 항목 | 값 |
|---|---|
| 다운로드 | 1,000 도메인, **623 GB** (`data/`) |
| 온도 × 리플리카 | 5 × 5 = 도메인당 25 궤적 |
| 궤적당 프레임 | 대부분 500 (최소 30) |
| 시간 해상도 | **1 ns/frame** (논문 확정, 파일에는 없음) |
| 좌표 / 힘 | Å / kcal/mol/Å (파일의 `unit` 속성에서 읽음) |
| 수소 | **저장되어 있음** (전형적 도메인에서 1126원자 중 558개) |

**중요:** `MDensemble/`의 mdCATH 사본은 읽기 전용이며 이 프로젝트는 별도 사본을 쓴다.

### 3.2 이번 학습에 사용한 부분

| 단계 | 결과 |
|---|---|
| 다운로드 | 1,000 도메인 |
| `max_residues: 250` 통과 | **907 도메인** (91%), 평균 118 잔기 |
| 도메인 단위 분할 (seed 0, val 20%) | **726 train / 181 val** |
| 궤적당 40 프레임 (≈12.8 ns 간격) | **725,977 train / 180,990 val 프레임** |
| 검증 서브샘플 | 2,400 프레임 (181개 도메인에 균등 stride) |

분할은 **프레임 열거 이전에 도메인 단위로** 수행한다. 한 단백질의 연속 프레임은 서로 강하게
상관되어 있어, 프레임 단위 분할은 일반화가 아니라 암기를 측정한다.

### 3.3 CHARMM 명명 함정

`data/residue_constants.py`가 세 가지를 처리한다:

1. **`HSD` / `HSE` / `HSP`** — CHARMM의 히스티딘 세 형태
2. **말단 캡** (`CAY HY1 HY2 HY3 CY OY` / `NT HNT CAT HT1 HT2 HT3`) — 말단 잔기에 병합되므로
   `CAY`를 알파 탄소로 착각하면 안 된다
3. **ILE `CD`** — 표준 PDB의 `CD1`이 아님

검증: 1000 도메인 / 136,825 잔기에서 **미확인 잔기 0개**.

### 3.4 발견된 업스트림 데이터 결함

**전수 감사 결과 (11,603,224 프레임 전량 스캔):**

| 결함 | 규모 | 조치 |
|---|---|---|
| `forces == coords` | 100 궤적 / 5 도메인 | `force_valid=False`로 라벨 무효화, 좌표는 사용 |
| 좌표 포화 (INT_MAX) | 87 프레임 / 15 도메인 | 인덱스에서 제외 |
| **좌표 붕괴 (all-zero)** | **1 프레임 / 1 도메인** | 인덱스에서 제외 |
| 힘 라벨 non-finite | **0** | — |
| PBC 파손 | 0 (120 도메인 10,800 프레임 표본) | — |

**`forces == coords`** — 항상 같은 패턴이다: 리플리카 0–3이 5개 온도 전부에서 손상, 리플리카 4는
정상. 모든 파일이 HuggingFace의 기록된 크기와 일치하므로 다운로드 아티팩트가 아니라 **공개된
데이터셋 자체의 결함**이다. 원인(왜 하필 리플리카 0–3인지)은 밝히지 못했다.

**좌표 포화** — 모든 원자가 `2.14748e7 Å`에 있다. 이 값은 `INT_MAX / 1000 nm`로,
XTC가 좌표를 int32(1/1000 nm 단위)로 저장하다 오버플로해 INT_MAX로 포화한 흔적이다.

**좌표 붕괴** — `2qenA03/348/3` 프레임 447. 1,194개 원자가 전부 정확히 `(0,0,0)`이다.
할당만 되고 기록되지 않은 마지막 프레임이며 힘 라벨은 정상이다. **이 프레임 하나가 학습 실행
3번을 죽였다** (§5.4).

### 3.5 필터링 파이프라인

```
download_mdcath.py  →  (자동) audit_mdcath_forces.py  →  mdcath_force_quarantine.json
                    →  (자동) audit_mdcath_coords.py  →  mdcath_coord_quarantine.json
                                     ↓
                       MdCathConfig.quarantine_path
                       MdCathConfig.coord_quarantine_path
                                     ↓
                       인덱스 구축 단계에서 제외 + 런타임 backstop
```

설계 원칙 세 가지:

1. **감사는 다운로드의 일부다.** README에 적어두면 잊힌다. `--skip-audit`로만 우회 가능.
2. **격리 파일이 지정되었는데 없으면 실행을 거부한다.** 이전에는 조용히 무필터로 학습됐다.
   `null`은 명시적 opt-out으로 계속 허용한다.
3. **감사와 런타임 backstop이 같은 프레임을 거부한다.** 두 불변량 — 크기(`> 1e4`)와
   **퍼짐**(`< 1 Å`) — 을 양쪽에 모두 둔다. 크기만 보면 all-zero 프레임을 놓친다.

격리는 **프레임 단위**다. 도메인이나 궤적 전체를 버리지 않는다. `2qenA03`은 448 프레임 중
1개만 빠지고 447개는 정상 사용된다.

## 4. 학습 설정

### 4.1 하드웨어와 분산

| 항목 | 값 |
|---|---|
| GPU | **4× H100 80GB (물리 인덱스 4–7)** |
| 분산 | `torchrun --nproc_per_node=4`, NCCL DDP |
| rank당 배치 | 24 |
| **effective batch** | **96** |
| DataLoader workers | rank당 8 (측정: 0 → 20 batch/s, 8 → 255, 16 → 263) |
| GPU 메모리 | 27–33 GB / 80 GB |
| 할당자 | `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` (없으면 예약 72 GB) |

**DDP에서 명시적으로 처리한 것 두 가지** — 둘 다 틀려도 손실 곡선에는 보이지 않는 종류다:

- **정규화 상수를 rank 0에서 broadcast한다.** 각 rank가 자기 shard로 fit하면 랭크마다 다른
  상수로 나눈 손실을 최적화하게 되고, 평균 gradient가 어떤 단일 목적함수도 내려가지 않는다.
- **검증은 rank 0이 단독으로, barrier 뒤에서 수행한다.** 샤딩된 지표를 랭크 평균한 것은
  그 지표가 아니다.

### 4.2 하이퍼파라미터

```yaml
learning_rate: 1.0e-3          # §5.4 참조 — 3e-3은 두 번 죽었다
warmup_steps: 2000
lr_schedule: cosine            # → 0.05× (최종 5e-5)
weight_decay: 0.0
grad_clip: 10.0
max_steps: 120000              # ≈15.9 epoch
seed: 0
use_energy_branch: false
```

**warmup이 필요한 이유:** 헤드가 log-variance를 출력하고 NLL이 `exp(logvar)`로 나눈다.
초기에 과한 step 한 번이 분산을 수천 step 걸려야 빠져나오는 곳에 박아버릴 수 있다.

### 4.3 내구성 장치

11.6M 프레임 중 하나가 15시간짜리 실행을 죽여서는 안 된다.

- **non-finite 배치 스킵** — `backward`는 **항상** 실행하고 `optimizer.step()`만 보류한다.
  DDP는 forward마다 정확히 한 번의 backward를 기대하기 때문이다. 오염된 gradient는 다음
  `zero_grad(set_to_none=True)`가 버리므로 가중치나 Adam moment에 닿지 않는다.
- **스킵 결정은 all-reduce로 집단 결정한다.** 한 rank만 건너뛰면 복제본들이 조용히 서로 다른
  모델이 되고 DDP는 그것을 모른 채 계속 평균한다.
- **연속 20회 스킵 시 중단** — 나쁜 프레임이 아니라 발산이라는 뜻이다.
- **non-finite 가중치는 체크포인트하지 않는다.** NaN을 충실히 저장하는 체크포인트는 존재 이유가 없다.
- **스킵 시 상태 덤프** — 가중치·배치·gradient를 rank별로 저장. 이것이 §5.4의 원인 규명을 가능하게 했다.
- **원자적 체크포인트** — tmp 저장 후 rename.

| 은닉 잔차 | 0.9742 | 77.5° | 0.185 | 38.97 | 40.00 | 34.87 | 5% |

집계 일관성 손실 0.0122. 평가 표본: 원자 2,176,877개 / 잔기 275,467개.

**지표 읽는 법**

- `rel. RMSE` = RMSE ÷ (0을 예측했을 때의 RMSE). **1.0 = 아무것도 배우지 못함**, 0.0 = 완벽.
  RMSE 단독으로는 해석이 불가능하다 — mdCATH 원자 힘 크기가 25–50 kcal/mol/Å이라
  RMSE 40이 잘한 건지 아무것도 안 한 건지 구분되지 않는다.
- `각도` = 예측 벡터와 정답 벡터 사이의 실제 각도. **90° = 무작위 방향**(3D에서 랜덤 두 벡터의
  평균), 0° = 방향 완벽. 크기 오차는 보지 않는다.
- 두 지표가 모두 필요한 이유: `rel`은 방향과 크기가 섞여 있어, 모델이 자신 없을 때 예측을 0쪽으로
  줄이면(통계적으로 옳은 행동) 방향을 못 맞춰도 `rel`이 내려간다. 각도는 이 몸사리기에 속지 않는다.

### 5.3 해석

**원자 힘은 학습되었다.** 24°는 무작위(90°)에서 한참 떨어져 있고 분산의 85%를 설명한다.
이것이 Phase 2가 실제로 쓸 신호다.

**잔기 힘·토크의 벽은 데이터 부족이 아니다.** 근거 두 가지:

1. 도메인을 40 → 726으로 **18배** 늘렸는데 잔기 힘은 0.70 → 0.674로 **3.6%**만 움직였다.
2. step 34,000 이후 정지했다. 남은 86,000 step은 아무것도 더하지 않았다.

**가설(확정 아님):** 잔기 힘은 원자 힘의 합이므로 분자 내부 결합력이 뉴턴 3법칙으로 상쇄되고,
남는 것은 알짜 외력인데 거기서는 **파일에 존재하지 않는 용매**가 지배한다.
뒷받침하는 수치 — 원자 |f| 평균 38.4인데 잔기 |F| 평균은 51.8로,
무상관 가정의 기댓값 √8 × 38 ≈ 108보다 훨씬 작다. 상쇄가 실제로 일어나고 있다는 뜻이다.
이것이 맞다면 이 벽은 모델 용량이 아니라 **정보의 부재**이고 현재 구조로는 넘을 수 없다.

**은닉 잔차 헤드는 사실상 실패했다** (rel 0.974, 77.5°, cosine 0.185).
설계 문서는 이 항이 식별 불가능하다고 보고 비활성화를 지시했다. mdCATH가 수소를 저장하므로
*식별은 가능하다*는 것이 반론이었고 — 측정된 잔차는 heavy-only 잔기 힘의 0.58–0.71배(평균 0.63)로
무시할 크기가 아니다 — 실제로 활성화했다. 결과는 **식별 가능한 것과 예측 가능한 것은 다르다**는
것이다. 잔기 스칼라 특징만으로 수소에 걸리는 힘을 예측하는 것은 이 구조로는 되지 않는다.

**에너지 분기는 이번 학습에서 껐다.** 3-arm ablation 결과 동일 step에서 원자/잔기/토크 지표가
동일한데 step 비용이 2.6배였다. `-∇U`와 보존력/잔차 분리는 Phase 1의 물리 산출물이므로
**별도의 평가용 모델로 복원해야 한다** (§7).

> 근본적 한계: 용매와 운동량을 적분해 없앤 뒤 단백질에 남는 유효 힘은 **단백질 좌표만의 어떤
> 퍼텐셜의 기울기도 아니다.** `-∇U`가 힘을 전부 설명하는 것은 원리적으로 불가능하며 코드도
> 둘을 같다고 놓지 않는다.

### 5.4 학습 중 발견한 버그와 수정

**데이터: collapsed 프레임 (실행 3번을 죽인 원인)**

`2qenA03/348/3` 프레임 447. 세 가지가 겹쳐 규명이 오래 걸렸다:

1. **크기 기반 감사로는 원리적으로 못 잡는다.** 좌표가 전부 정확히 0이라 `|coord| = 0`이고
   임계값을 아무리 조여도 통과한다. 옳은 불변량은 **공간적 퍼짐**이었다.
2. **반드시 샘플링된다.** `np.linspace(0, n-1, k)`는 항상 마지막 프레임을 포함한다.
   1160만 분의 1짜리 결함과 그것을 골라내는 샘플러가 만나 확률이 1이 됐다.
3. **DDP가 범인을 가렸다.** 겹친 원자가 backward에서 NaN을 만들고 gradient all-reduce가
   그것을 네 rank 전부에 복사한다. rank 0에서는 "손실 유한 + gradient NaN"으로 보여
   모델의 backward 버그로 오독하게 된다. 실제로 손실이 NaN이었던 것은 rank 2뿐이었다.

검증: 전수 감사가 찾은 collapsed 프레임 **1개**와, 실행에서 관측된 **에폭당 정확히 1회** 스킵이
독립적으로 일치한다.

**코드: `torch.cdist` 불안정 공식**

기본 모드는 25행 초과 시 `‖a‖² + ‖b‖² − 2a·b`로 전환되는데, 좌표가 측정 거리보다 훨씬 클 때
파국적으로 불안정하다. 결과적으로 **같은 구조라도 박스 안 위치에 따라 다른 그래프가 만들어졌다.**
평행이동 +1000 Å에서 원자 edge가 120,326개 중 +1,488/−360개 변했다(비대칭 = 체계적 편향).
실제 데이터 좌표(최대 246 Å)에서의 영향은 714,500개 중 79개(0.011%)로 작지만 물리와 무관한
변수가 노이즈로 들어가는 것은 맞다. `compute_mode="donot_use_mm_for_euclid_dist"`로 수정,
평행이동 불변성 테스트로 고정.

**코드: 절대 박스 좌표 조건수**

mdCATH 좌표는 절대 박스 위치로 최대 ~460 Å인데 모델이 쓰는 것은 전부 수 Å짜리 차이다.
TF32에서 손실이 **2.43 → 12.68**로 뛰는 것으로 드러났다. 프레임별 중심 정렬 후 같은 전환이
**0.0008**만 움직인다(12,800배 개선). 모델은 평행이동 불변이므로 물리적으로 no-op다.

**기각된 가설들** (반복하지 않기 위해 기록):

| 가설 | 검증 | 결과 |
|---|---|---|
| lr 3e-3 발산 | 3-arm 스윕 + 실행 2회 | 실행 1의 사망은 lr이 아니었음 |
| 힘 라벨 손상 | 11,603,224 프레임 | 0건, 최대 277.6 kcal/mol/Å |
| 원자 중복 | `2akcA00` 991 프레임 | 최소 연결 거리 1.107 Å |
| `(chain, resid)` 충돌로 잔기 병합 | 1000 도메인 | 0건, 전부 단일 체인 |
| 모델 내 0-나눗셈 | frames/radial/edges/e3nn | 전부 가드 있음 |
| backward에서 태어난 NaN | 실패 시 가중치로 재생 | rank 0에서는 forward·backward 모두 정상 |

마지막 행이 교훈이다. rank 0 덤프 재생이 아무것도 재현하지 않은 것은 데이터가 무죄라는
증거처럼 보였지만, 실은 **rank 0의 데이터가** 무죄라는 증거였다. 4-rank all-reduce에서 한 rank만
확인하고 일반화한 것이 가장 비용이 큰 오류였다.

## 8. Phase 2 인계

`LocalPhysicsModel.latent_contract()`가 반환하는 약속:

```
physics_latent_irreps : 64x0e+16x1o+8x2e
physics_latent_dim    : 152
row_order             : batch.residues와 정렬 (잔기 노드 인덱스)
frame                 : global
target_scope          : heavy_atom
predicts_hidden_force : True
num_cycles            : 2
lmax                  : 2
```

Phase 2는 `encoder.num_cycles`와 irreps multiplicity를 키우고 그 위에 전이 모듈을 올린다.
여기의 어떤 클래스도 대체하지 않는다 — 깊이와 폭은 설정값이므로 Phase 2가 같은 클래스를 로드한다.

`ps_per_frame: 1000.0`이 Phase 2의 1/2/4/8/16 ns 다중 lag 학습에 쓰인다 (각각 1/2/4/8/16 프레임).
Phase 1은 프레임 단위 힘 지도학습이라 이 값을 쓰지 않는다.
